# TimeRecording 功能介绍与使用说明

TimeRecording 是一款 Android 平台的轻量级项目时间记录与统计工具，支持多项目并行计时、暂停与继续、跨天自动分段、甘特图与柱状图可视化，以及壁纸个性化。本文档介绍它的功能设计、操作方式、技术实现与常见问题。

## 概述

TimeRecording 面向一个具体的日常问题：当你同时在推进多个项目时，很难说清每个项目实际投入了多少时间。应用把"开始、暂停、继续、结束"这一整套计时流程做成了极简的两步操作，自动记录每一次有效的工作时段，再把结果用甘特图和柱状图呈现出来。

所有项目与会话数据都保存在本地的 Room 数据库中，不依赖账号，也不上传任何个人数据。应用唯一会访问网络的地方是检查版本更新，且只读取一个公开的版本描述文件。

- **多项目并行计时** 每个项目拥有独立的状态机，可同时处于计时状态，互不干扰。
- **前台服务保障** 计时期间运行前台服务并在通知栏显示状态，降低应用被系统回收导致计时中断的概率。
- **跨天自动分段** 会话跨越零点时自动在 00:00 处切分为两条记录，分别归属到对应的日期。
- **甘特图可视化** 统计页以 24 小时为纵轴、每个项目为一列，直观呈现一天的作息分布。
- **柱状图统计** 详情页按日期聚合每日有效时长，并支持自定义图表颜色。
- **壁纸个性化** 可从相册选择图片，裁剪后作为应用的全屏背景。

## 功能详解

### 项目管理

项目是应用的基本组织单元。每个项目拥有独立的名称、计时状态和一组历史会话记录，彼此之间完全隔离。

**项目操作一览**

| 操作 | 触发方式 | 行为说明 |
| --- | --- | --- |
| 添加项目 | 在输入框填写名称后点击"添加" | 名称为空时提示"项目名不能为空"；添加成功后提示"已添加：项目名"，输入框自动清空，新项目追加到列表末尾 |
| 重命名 | 点击项目名称文字 | 先弹出输入框修改名称，再弹出确认框二次确认。名称为空时提示"名称不能为空"，与原名称相同时提示"名称未变化" |
| 删除项目 | 仅 idle 状态下点击"删除" | 弹出二次确认对话框并提示"该操作不可撤销"。删除项目会级联删除其全部历史会话记录。计时中或暂停状态下该按钮自动隐藏，避免误删 |
| 查看详情 | 点击卡片上的详情按钮 | 进入项目详情页查看柱状图与会话列表。计时中的项目不会因此暂停，返回后计时继续进行 |

### 计时器

每个项目在三种状态之间循环，构成一个简单的状态机。卡片上的主按钮文字会随状态变化，旁侧按钮的可见性也随之调整。

**计时状态机**

| 当前状态 | 主按钮 | 旁侧按钮 | 点击主按钮后的行为 |
| --- | --- | --- | --- |
| `idle` | 开始 | 仅"删除" | 记录会话开始时间，进入计时状态，并启动前台计时服务 |
| `running` | 暂停 | "结束" | 计算自上次开始或继续以来的增量，累加到已计时时长，进入暂停状态 |
| `paused` | 继续 | "结束" | 以当前时间作为新的增量起点回到计时状态，暂停期间的时间不计入 |

> **结束计时**
>
> 点击"结束"会终止当前会话。若累计有效时长不足 1 分钟，该次会话不会被写入记录，并提示"本次计时少于1分钟，不记录"；达到 1 分钟及以上时，会生成一条包含开始时间、结束时间和有效时长的会话记录，项目回到 idle 状态。

卡片上显示的时长始终是**当前这一次会话**的累计值，而不是项目的历史总时长。项目的历史总时长可以在详情页查看。运行中的项目每秒刷新一次显示，因此界面上的秒数会实时跳动。

### 跨天自动分段

通宵工作或忘记结束计时是常见情况。如果一条会话跨越了午夜零点，直接按开始时间归属日期会让统计数据严重失真。应用的处理方式是在 00:00 处自动切分会话。

- **计时进行中跨天** 前一天的部分从会话开始时间结算到 00:00 并写入记录；新的一天从 00:00 重新开始计时，状态保持为计时中，无需人工干预。
- **暂停状态下跨天** 直接把已暂停的这段时长整体结算成一条记录并复位项目状态。
- **有效性判断** 切分后任一部分的时长若不足 1 分钟，该部分不会被写入记录。

该检查在三个时机自动执行：应用启动时、计时页回到前台时、以及日期发生变化时（计时页与前台服务每秒检测一次日期）。

### 项目详情

详情页从数据库加载指定项目的完整数据，包含以下内容：

- **项目名称与总计时** 展示项目名，以及该项目所有历史会话有效时长的总和。
- **每日柱状图** 按日期（以会话开始时间归属）聚合当日有效时长，纵轴单位为秒，横轴为日期。支持拖动、缩放与双指缩放，同屏最多展示约 10 天。数值达到 1 小时以上时以小时显示，否则以秒显示。当项目没有任何会话时，图表自动隐藏。
- **自定义颜色** 点击"自定义颜色"按钮弹出 RGB 三通道滑块，拖动时上方色块实时预览效果。确认后颜色保存在本地设置中，并立即应用到柱状图。下次进入详情页会自动沿用该颜色。
- **会话列表** 以列表形式展示所有历史会话，每条记录包含开始时间、结束时间和持续时长。

### 统计甘特图

统计页使用自定义 Canvas 绘制的甘特图，纵轴为 0 到 24 时，每小时一条网格线，时间标签固定在左侧；每个项目占一列，列顶显示项目名称，过长时自动省略。

列内的彩色圆角竖条表示该日期内的会话时段：只有开始时点落在所选日期的会话会被绘制，竖条的上下位置由会话的开始与结束时刻映射到 24 小时坐标决定。每列的最小宽度为 65dp，当项目较多、总宽度超出屏幕时，图表区域可以横向滚动查看。

颜色使用 8 色调色板按项目顺序循环分配：当项目数超过 8 个时，第 9 个项目开始重复使用第一组颜色。

**日期导航操作**

| 操作 | 行为 |
| --- | --- |
| 左箭头 / 右箭头 | 向前或向后切换一天，图表立即刷新 |
| 点击中间日期文字 | 弹出日期输入框，可手动填写年、月、日跳转到任意日期。输入不完整或月份日期越界会被拦截，不存在的日期（如 2 月 30 日）同样会被拒绝 |
| 回到今天按钮 | 立即跳回当天并提示"已回到今天" |

当数据库中没有项目时，图表区域会显示"暂无项目数据"的占位提示。

### 壁纸设置

壁纸流程围绕系统相册与裁剪工具展开：

1. 点击"从相册选择"，系统相册以图片选择模式打开。
2. 选中图片后进入裁剪界面，裁剪框按当前屏幕的宽高比锁定，输出分辨率上限为屏幕分辨率。
3. 确认裁剪后，图片被复制保存到应用私有目录的 `wallpaper.jpg`，并把路径写入本地设置，同时提示"壁纸已保存"。
4. 主界面每次回到前台时读取该文件，铺满整个根布局作为全屏背景。

点击"清除壁纸"会移除路径记录并清空预览，应用恢复默认的透明背景。壁纸保存在应用私有目录中，其他应用无法直接访问。

### 检查更新

应用提供自动与手动两种更新检查方式，数据来源是一个公开的版本描述文件，其中包含版本号、版本名称、下载地址和更新日志。

- **自动检查** 进入主界面时在后台静默执行。只有确实发现更高版本时才弹窗提示，没有新版本或网络异常时不会打扰用户。
- **手动检查** 在设置页点击"检查更新"触发，无论结果如何都会给出明确反馈：已是最新版本、发现新版本，或"网络异常，无法检查更新，请稍后重试"。

> **更新提示**
>
> 发现新版本时弹出的对话框不可点击外部关闭，需明确选择"立即更新"或"稍后"。"立即更新"会跳转到系统浏览器或应用商店打开下载地址，应用本身不会在后台自动下载或安装任何内容。

## 使用说明

### 首次使用

1. 打开应用，默认进入"计时"页。在顶部输入框中填写项目名称（例如"写论文"），点击"添加"。
2. 项目卡片出现在列表中。点击"开始"启动计时，此时通知栏会出现计时提示，前台服务开始运行。
3. 工作中需要短暂休息时点击"暂停"；休息结束后点击"继续"恢复，暂停期间的时间不会被计入。
4. 完成一段工作后点击"结束"。有效时长达到 1 分钟以上时，这次会话会被保存到历史记录中。
5. 切换到"统计"页，甘特图会显示各项目在一天中的时间分布。
6. 点击卡片上的详情按钮，可以查看该项目的每日柱状图与完整会话列表。

### 多项目并行计时

应用允许同时有多个项目处于计时状态。此时通知栏会显示"正在计时 项目数量 个项目"，并在副标题中列出全部项目名称（单个项目时直接显示"正在计时: 项目名"）。

每个项目的计时完全独立计算，切换页面、暂停某个项目都不会影响其他项目。当所有项目都结束或回到 idle 状态后，前台服务会自动停止，通知栏提示随之消失。

### 查看统计数据

1. 点击底部导航栏的"统计"标签进入统计页。
2. 甘特图默认显示当天的数据。点击左右箭头切换日期，或点击"回到今天"快速返回。
3. 点击中间的日期文字，可以手动输入年、月、日跳转到任意日期。
4. 每列代表一个项目，列顶是项目名称，列内的彩色竖条表示该日期内的会话时段。项目较多时左右滑动查看。
5. 最左侧是固定的 0 到 24 时时间轴，用于对照竖条所对应的具体时刻。

### 自定义壁纸

1. 点击底部导航栏的"设置"标签。
2. 点击"更换壁纸"，进入壁纸设置页。
3. 点击"从相册选择"，在系统相册中挑选一张图片。
4. 裁剪界面会按屏幕比例锁定裁剪框，调整后确认，图片即被保存为应用背景。
5. 返回主界面即可看到效果；如需恢复默认背景，再次进入该页点击"清除壁纸"。

### 修改图表颜色

1. 从计时页点击某个项目的详情按钮进入详情页。
2. 点击柱状图下方的"自定义颜色"按钮。
3. 拖动红、绿、蓝三个滑块调整颜色，上方色块会实时预览效果。
4. 点击"确定"保存，柱状图会立即使用新颜色绘制。

### 查看本文档

1. 点击底部导航栏的"设置"标签。
2. 点击"关于应用"，即可在应用内打开本文档。
3. 文档支持双指缩放；点击左上角返回按钮或使用系统返回键退出。

## 技术架构

### 整体架构

应用采用 ViewModel + Repository 的分层架构，数据持久化使用 Room 数据库。界面层基于传统 Android View 体系，由 RecyclerView 承载列表、BottomNavigationView 承载底部导航，三个页面均为 Fragment，详情页与设置类页面为独立的 Activity。

**架构层次说明**

| 层次 | 职责 | 关键类 |
| --- | --- | --- |
| UI 层 | 界面渲染与用户交互 | HomeFragment、StatisticsFragment、WallpaperFragment、DetailActivity、AboutActivity、WallpaperSettingsActivity、GanttChartView、GanttTimeAxisView |
| ViewModel 层 | 持有并管理 UI 状态，隔离业务逻辑与界面 | HomeViewModel、StatisticsViewModel、DetailViewModel |
| Repository 层 | 统一数据访问入口，封装全部数据库操作与启动时的恢复逻辑 | ProjectRepository（单例） |
| 数据层 | Room 数据库、实体与数据访问对象 | AppDatabase、ProjectDao、SessionDao、ProjectEntity、SessionEntity |
| 服务层 | 前台服务保障计时可靠性，并在后台完成跨天检测 | TimerService |
| 工具层 | 版本检查与旧数据迁移 | UpdateChecker、DataMigration |

### 数据模型

应用有两个核心实体，构成一对多关系：

- **Project** 包含名称、计时状态（idle / running / paused）、本次会话开始时间、增量计算起点时间和累计已计时时长。一个项目对应多条会话记录。
- **Session** 记录一次完整的计时会话，包含开始时间、结束时间和有效时长（不含暂停时间）。会话通过外键关联到项目，删除项目时其全部会话会被级联删除。

### 数据流

用户操作触发 ViewModel 方法，ViewModel 通过协程调用 Repository，Repository 执行 Room 的数据访问操作。查询以 Flow 形式返回，经转换后暴露为 LiveData 供界面观察，界面收到新数据即刷新列表。整个过程是单向数据流：

```
用户操作 → ViewModel → Repository → Room DAO → Flow → LiveData → Fragment → UI
```

由于数据库变更会自动推送到界面，任何一次添加、重命名、删除或计时状态变化都会即时反映在列表中，无需手动刷新。

### 计时可靠性机制

计时不依赖内存中的计数器，而是通过三层机制保证结果可靠：

1. **前台服务** 计时期间启动前台服务，持续展示一条常驻且静音的通知，显著降低进程被系统回收的概率。服务会每秒核实一次是否仍有项目在计时，全部结束后自动停止。
2. **时间戳差值计算** 有效时长由系统时间戳的差值累加得出，而不是由定时器向上计数。因此即使进程被中断，只要时间戳还在，时长就不会丢失。
3. **启动自动恢复** 仓库层初始化时会检查所有处于计时状态的项目，用当前时间减去记录的增量起点，把进程中断期间遗漏的时长补写回数据库，再以当前时间作为新的起点继续计时。

### 跨天分段机制

跨天检测由仓库层统一实现，计时页与前台服务在日期变化时调用。对于正在计时的项目，若增量起点早于当天零点，则前一天的时长按 `累计时长 + (零点 - 增量起点)` 结算，新的一天从零点重新起算；对于已暂停的项目，直接把整段时长结算为一条记录并复位状态。结算时同样执行 1 分钟的有效性检查。

### 数据迁移

应用内置数据迁移机制。首次启动时会检测旧版本遗留在本地设置中的 JSON 数据，将其解析后逐条写入 Room 数据库，写入成功后写入迁移完成标记，后续启动不再重复执行。如果迁移过程中发生异常，旧数据会原样保留，下次启动时重新尝试，不会造成数据丢失。

> **隐私说明**
>
> 所有项目数据与计时记录都保存在设备本地的 Room 数据库中，应用不收集、不上传任何个人信息。唯一的网络行为是读取一个公开的版本描述文件，请求中不包含任何用户数据。壁纸裁剪后保存在应用私有目录，其他应用无法访问；卸载应用时，数据库与壁纸文件会一并被系统清除。

## 常见问题

### 应用被系统清理后，计时会丢失吗？

不会。计时基于系统时间戳的差值计算，而不是依赖内存中的计数器。应用下次启动时，仓库层会自动检测所有处于计时状态的项目，用当前时间减去记录的增量起点，把中断期间的时长补回数据库。前台服务的存在进一步降低了应用被回收的可能性。

### 可以同时计时多个项目吗？

可以。每个项目拥有独立的状态机，多个项目能同时处于计时状态，互不干扰。通知栏会显示"正在计时 N 个项目"并列出全部项目名称。

### 不足 1 分钟的计时会怎样？

点击"结束"时如果累计有效时长不足 60 秒，这次会话不会被保存，应用会提示"本次计时少于1分钟，不记录"，项目回到 idle 状态。这条规则同样适用于跨天分段产生的每一段。

### 通宵计时会算在哪一天？

算在实际发生的那一天。会话跨越零点时会在 00:00 处自动切分为两条记录，前一段归属前一天，后一段归属当天。因此在统计页查看任何一天，看到的都是真实分布在该天的时间。

### 删除项目后数据能恢复吗？

不能。删除项目时，该项目及其全部历史会话会从数据库中永久删除。删除前会弹出二次确认对话框，且该按钮仅在项目处于 idle 状态时可见，以避免误操作。

### 为什么甘特图上看不到某次计时？

甘特图按会话的开始时间归属日期，只有开始时点落在所选日期的会话才会被绘制，完整横跨数小时的会话会显示为对应长度的一条竖条。如果某次计时不足 1 分钟，它本就不会被写入记录，自然也不会出现在图表中。

### 甘特图最多能显示多少个项目？

没有数量限制。每列至少有 65dp 的宽度，项目较多时图表区域可以左右滚动。颜色使用 8 色调色板循环分配，超过 8 个项目后颜色会从第一个开始重复。

### 从旧版本升级后数据还在吗？

在。应用内置数据迁移机制，首次启动新版本时会自动把旧版存储在本地设置中的 JSON 数据迁移到新的数据库中，整个过程在后台执行，对用户透明。若迁移过程被中断，旧数据会保留，下次启动时重新尝试。

### 检查更新失败怎么办？

手动检查时若无法连接服务器，会提示"网络异常，无法检查更新，请稍后重试"。请确认设备网络可用后重试。自动检查失败时不会打扰用户，仅在发现新版本时提示。
